# Шаблон: контракт инструмента

## Назначение

Заполняется на каждый инструмент, доступный агенту. Потребители — реализующий инструмент разработчик и сама модель: описание из этого документа попадает в определение инструмента.

## Обязательные поля

| Поле | Считается заполненным, если |
|---|---|
| Когда применять | назван признак ситуации, а не перечень возможностей |
| Когда не применять | назван хотя бы один случай и альтернатива |
| Схема входа | у каждого параметра есть пример значения, а не только тип |
| Схема выхода | описана структура успешного результата |
| Коды ошибок | у каждого есть `retryable` и `remediation` |
| Побочные эффекты | указано, что меняется во внешнем мире |
| Идемпотентность | назван ключ или явно записано, что операция не идемпотентна |
| Класс риска | один из четырёх, с указанием подтверждения |

Отсутствие раздела «когда не применять» — самая частая причина того, что модель выбирает не тот инструмент.

## Форма

```markdown
# Инструмент: <имя>

## Назначение
Одна возможность: <что делает>

## Когда применять
<признак ситуации>

## Когда не применять
| Ситуация | Что использовать вместо |
|---|---|

## Ограничения
<чего инструмент не умеет; какие входные данные не поддерживает>

## Схема входа
| Параметр | Тип | Обязателен | Пример | Ограничения |
|---|---|---|---|---|

## Схема выхода
<структура успешного результата>

## Ошибки
| Код | Причина | retryable | remediation |
|---|---|---|---|

## Побочные эффекты
<что меняется вне агента>

## Идемпотентность
Ключ: <какой> либо «операция не идемпотентна»

## Ограничения выполнения
Таймаут: <значение>
Повторы: <политика>
Права: <чтение/запись/сеть/секреты>
Песочница: <да/нет, какая>

## Класс риска и подтверждение
Класс: <read-only | обратимая запись | внешняя коммуникация или деньги | необратимое>
Подтверждение: <когда требуется, кем даётся, где реализовано>

## Провенанс результата
<как результат связывается с конкретным вызовом>
```

## Заполненный пример

```markdown
# Инструмент: process_refund

## Назначение
Одна возможность: провести возврат средств по существующему заказу.

## Когда применять
Возврат согласован, сумма проверена, заказ находится в допустимом окне.

## Когда не применять
| Ситуация | Что использовать вместо |
|---|---|
| Нужно узнать статус заказа | query_order |
| Нужно проверить допустимость возврата | check_refund_window |
| Клиент просит частичную компенсацию без возврата | escalate_to_operator |

## Ограничения
Не проверяет допустимость возврата самостоятельно. Не работает с заказами
в валюте, отличной от валюты заказа. Не поддерживает частичный возврат
позиции — только сумму целиком или её часть.

## Схема входа
| Параметр | Тип | Обязателен | Пример | Ограничения |
|---|---|---|---|---|
| order_id | string | да | "ORD-2026-88412" | формат ORD-YYYY-NNNNN |
| amount | decimal | да | 1250.00 | > 0, не больше суммы заказа |
| currency | string | да | "RUB" | совпадает с валютой заказа |
| reason_code | enum | да | "damaged_goods" | из справочника причин |
| idempotency_key | string | да | "refund-ORD-2026-88412-1" | уникален на попытку |

## Схема выхода
{"transaction_id": "TRX-...", "status": "completed|pending",
 "amount": 1250.00, "processed_at": "2026-08-05T10:12:00Z"}

## Ошибки
| Код | Причина | retryable | remediation |
|---|---|---|---|
| RATE_LIMITED | превышена частота обращений | да | повторить через указанное время |
| GATEWAY_TIMEOUT | платёжный шлюз не ответил | да | повторить с тем же ключом идемпотентности |
| AMOUNT_EXCEEDS_ORDER | сумма больше суммы заказа | нет | пересчитать сумму по данным заказа |
| ORDER_NOT_FOUND | заказа нет | нет | проверить идентификатор через query_order |
| WINDOW_EXPIRED | вне окна возврата | нет | запросить одобрение оператора |

## Побочные эффекты
Списание средств со счёта продавца и зачисление клиенту. Создание записи
транзакции. Отправка уведомления платёжной системой.

## Идемпотентность
Ключ: idempotency_key. Повтор с тем же ключом возвращает исходную
транзакцию и не создаёт вторую.

## Ограничения выполнения
Таймаут: 30 секунд.
Повторы: до 3 при retryable-ошибках, экспоненциальная задержка.
Права: запись в платёжную систему, сеть к домену шлюза.
Песочница: нет, вызов внешнего API через выделенный сервис.

## Класс риска и подтверждение
Класс: необратимое, деньги.
Подтверждение: оператор при сумме свыше 5000 или при истёкшем окне.
Реализовано в policy.py до вызова инструмента, не в промпте.

## Провенанс результата
transaction_id сохраняется вместе с run_id и call_id; связь позволяет
восстановить, какой шаг агента вызвал списание.
```
