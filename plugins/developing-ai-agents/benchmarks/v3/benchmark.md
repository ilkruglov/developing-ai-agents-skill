# Benchmark v3: версия 0.5.0 против 0.4.0

Сравниваются две версии скилла между собой. Это не то же самое, что сравнение
«со скиллом против без скилла» из benchmark v2.

## Метод

26 сценариев, по одному прогону на конфигурацию. Оценка слепая: оценщик получал
пару ответов как A и B без указания версии; раскладка задавалась хешем
идентификатора сценария. Критерий засчитывался, только если ответ выполнял его
явно.

## Результат

| Метрика | 0.5.0 | 0.4.0 |
|---|---:|---:|
| Критериев выполнено | 95/105 (90.5%) | 96/105 (91.4%) |
| Побед в слепом сравнении | 8 | 11 |
| Ничьих | 7 | |

Расхождения по критериям: 0.5.0 лучше в 7 случаях, 0.4.0 — в 8.
Точный тест McNemar: p = 1.000. Биномиальный тест побед: p = 0.648.
Стандартная ошибка доли около 2.9 процентного пункта при наблюдаемой разнице
в 1.0 пункта.

## Вывод

**Улучшение не доказано.** Разница между версиями лежит внутри шума, и по
собственному правилу скилла такая разница решением не является.

Отдельно стоит отметить ограничения этого прогона, из-за которых отсутствие
разницы не следует читать как доказательство эквивалентности:

- один прогон на конфигурацию вместо нескольких — разброс самих прогонов не
  измерен;
- обе версии выполняют около 91% критериев, то есть набор близок к насыщению и
  плохо различает конфигурации в верхней части шкалы;
- критерии писались под сценарии, существовавшие в 0.4.0, и напрямую не
  проверяют новые слои: playbooks и шаблоны оцениваются лишь косвенно, через
  качество итогового ответа.

| Сценарий | 0.5.0 | 0.4.0 |
|---|---:|---:|
| coding-agent-recovery | 3/5 | 5/5 |
| silent-hang-detection | 2/3 | 3/3 |
| tool-explosion | 2/3 | 3/3 |
| event-driven-idempotency | 3/5 | 4/5 |
| training-strategy | 4/5 | 5/5 |
| realtime-stale-action | 4/5 | 5/5 |
| source-grounded-review | 4/5 | 5/5 |

Общее у этих сценариев: они требуют конкретного механизма (идемпотентность,
восстановление, обнаружение зависания, сокращение числа инструментов), который
в 0.4.0 был изложен прямо в `SKILL.md`, а в 0.5.0 вынесен в конспект главы.
Агент до этого слоя не всегда доходит — маршрут ведёт его в playbook, который
описывает процедуру, но не содержит самого механизма.


## Итерация 0.5.1: возврат конкретики в ядро

По результатам прогона в `SKILL.md` возвращены механизмы, которых не хватало
отставшим сценариям: таксономия сбоев по четырём уровням, классификация ошибки
до счёта повторов, правило «неизвестный исход не равен неудаче» со сверкой
состояния провайдера, отпечаток повторяющегося вызова, мониторинг беззвучного
зависания, эскалация восстановления, состав durable checkpoint, послойное
раскрытие инструментов, проверка созданного инструмента перед публикацией,
набор race-тестов и ветка SFT после исправления интерфейса.

Восемь сценариев прогнаны повторно:

| Сценарий | 0.4.0 | 0.5.0 | 0.5.1 |
|---|---:|---:|---:|
| event-driven-idempotency | 4/5 | 3/5 | 5/5 |
| coding-agent-recovery | 5/5 | 3/5 | 5/5 |
| training-strategy | 5/5 | 4/5 | 5/5 |
| source-grounded-review | 5/5 | 4/5 | 5/5 |
| silent-hang-detection | 3/3 | 2/3 | 3/3 |
| tool-explosion | 3/3 | 2/3 | 3/3 |

| **Итого по восьми** | **34** | **26** | **34** |

Регрессия относительно 0.4.0 устранена: на этих сценариях версии сравнялись.

### Почему это не доказательство улучшения

Правка вносилась после того, как стало известно, какие именно критерии
провалены на этом наборе. Это настройка на тестовый набор — тот самый
антипаттерн, который скилл называет «тюнинг на holdout». Поэтому цифра 103/105
для 0.5.1 не является независимым измерением и в сводную таблицу README не
выносится:

- 8 сценариев прогнаны после правки, 18 — до неё; прогон смешанный;
- набор перестал быть независимым для оценки этой правки навсегда;
- подтвердить улучшение можно только на новом наборе, собранном без знания
  внесённых изменений.

Корректный вывод из итерации: **устранена конкретная регрессия**, обнаруженная
слепым сравнением. Утверждать, что 0.5.1 лучше 0.4.0, оснований нет.


## Проверка слоя шаблонов

Первый прогон не проверял шаблоны и playbooks напрямую: ни один сценарий не
требовал заполненного артефакта, и новый слой оценивался лишь через качество
свободного текста. Добавлены шесть сценариев, где ответом должен быть готовый
документ, а критерии соответствуют обязательным полям шаблона.

| Сценарий | 0.5.1 | 0.4.0 |
|---|---:|---:|
| artifact-tool-contract | 5/5 | 4/5 |
| artifact-eval-plan | 5/5 | 3/5 |
| artifact-harness-spec | 5/5 | 5/5 |
| artifact-memory-policy | 5/5 | 4/5 |
| artifact-trace-diagnosis | 5/5 | 5/5 |
| artifact-agent-design | 5/5 | 4/5 |
| **Итого** | **30/30** | **25/30** |

Расхождения: 0.5.1 лучше в 5 случаях, 0.4.0 — ни в одном. Точный тест
McNemar: p = 0.062.

Обе версии выдают именно документ, а не рассуждение о нём: базовая версия
справляется с формой сама. Разница — в полноте. Без шаблона теряются примеры
значений параметров, версии инструментов и окружения, сигнал срабатывания
отката, число подтверждений для записи памяти, терминальные состояния.

### Как это читать

Эффект направленный: пять расхождений из пяти в одну сторону. Но при выборке
в шесть сценариев p = 0.062 не достигает уровня 0.05, поэтому утверждать
значимое улучшение нельзя.

Выборка сознательно не расширялась после получения результата: добор
сценариев до пересечения порога — это остановка по достижении желаемого,
которая обесценивает сам порог. Корректный путь — заранее объявить больший
размер набора и прогнать его целиком.

Отдельное ограничение: критерии выведены из обязательных полей шаблонов, то
есть измеряют следование шаблону. Поля осмысленны сами по себе — пример
значения параметра, сигнал отката, терминальное состояние, — но нейтральным к
проверяемому решению этот набор не является.
