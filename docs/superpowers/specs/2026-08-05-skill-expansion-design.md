# Дизайн: расширение skill `developing-ai-agents` до полного справочника

Дата: 2026-08-05
Статус: утверждён пользователем, готов к планированию реализации

## 1. Задача

Довести `developing-ai-agents` с уровня «компактный operating manual» (183 строки
`SKILL.md` + 1462 строки справочников) до полного инженерного справочника по
разработке AI-агентов: глубокие конспекты всех глав книги, пошаговые процедуры
под типовые задачи, заполняемые артефакты и расширенный набор evals.

Ключевое требование к качеству: каждое фактическое утверждение, приписанное
книге, должно быть машинно проверяемо. Проверка реализуется как жёсткий гейт в
`scripts/validate.py`, падающий в CI.

## 2. Не-цели

Явно вне скоупа этой работы:

- обновление текста книги на актуальный upstream (книга остаётся на
  `97de455e9aa44cf9f93441ce0c771c9aa9643d92`, версия v1.2 — завершена);
- перевод `reference-answers.md` (файл появился в upstream после закреплённого
  коммита);
- перенос 133 изображений книги в бандл;
- изменение пайплайна перевода в соседнем репозитории `ilkruglov/ai-agent-book`;
- смена языка скилла (остаётся русский, `description` — английский для
  корректного триггеринга).

## 4. Ограничения, продиктованные best practices

Эти ограничения взяты из официального руководства Anthropic по авторингу
скиллов и из `superpowers:writing-skills`; они определяют структуру решения.

1. **Ссылки на файлы — один уровень от `SKILL.md`.** Агент, дошедший до файла
   через промежуточный хаб, часто читает его частично (`head -100`). Поэтому
   `references/chapters/index.md` как навигационный хаб упраздняется; все
   справочные файлы линкуются напрямую из роутера в `SKILL.md`.
2. **`SKILL.md` — до 500 строк.** Целевой бюджет: не более 300 строк, чтобы
   оставить запас и не платить контекстный налог на каждом вызове.
3. **Файл >100 строк начинается с оглавления.** Иначе при частичном чтении
   агент не видит охвата файла.
4. **Единая терминология.** Один термин на одно понятие во всех файлах;
   расхождения фиксируются в `glossary.md`.
5. **Не предлагать много вариантов без нужды.** Для каждой развилки — дефолт и
   явное условие отклонения от него.
6. **Iron Law: правка скилла требует падающего теста.** Прогон baseline и
   with-skill сценариев требует субагентов и выполняется только по явному
   разрешению пользователя (фаза 8).

### 5.1 Разделение ролей

Условие, при котором рост объёма не превращается в дублирование, — каждый слой
отвечает ровно на один вопрос:

| Слой | Вопрос | Форма |
|---|---|---|
| `SKILL.md` | что решить и куда пойти | правила + роутер |
| `chapters/` | что об этом говорит книга | конспект с дословными цитатами |
| `patterns.md` | какую конструкцию собрать | failure mode → механизм → проверка |
| `playbooks/` | что делать по шагам прямо сейчас | чеклист с гейтами |
| `templates/` | чем отчитаться | заполняемая форма |
| `antipatterns.md` | чего не делать и почему | симптом → причина → замена |

Материал, относящийся к чужому слою, не дублируется, а адресуется ссылкой.

## 6. Роутер в `SKILL.md`

Навигация организована по типу задачи пользователя, а не по структуре книги.
Роутер — таблица из трёх колонок: признак запроса, стартовый файл, чем добрать.

| Запрос выглядит как | Начни с | Добери при необходимости |
|---|---|---|
| спроектировать агента с нуля | `playbooks/design-agent.md` | `patterns.md`, `templates/agent-design.md` |
| разобрать trace, найти причину сбоя | `playbooks/diagnose-trace.md` | `chapters/ch02`, `ch04`, `templates/trace-diagnosis.md` |
| review существующей агентной системы | `playbooks/harness-review.md` | `chapters/ch01`, `ch05`, `antipatterns.md` |
| построить или починить evals | `playbooks/build-evals.md` | `chapters/ch06`, `templates/eval-plan.md` |
| память, RAG, самоулучшение | `playbooks/memory-design.md` | `chapters/ch03`, `ch08`, `templates/memory-policy.md` |
| голос, realtime, мультимодальность | `playbooks/realtime-latency.md` | `chapters/ch09` |
| один агент или несколько | `playbooks/multi-agent-choice.md` | `chapters/ch10` |
| контракт инструмента, безопасность действий | `templates/tool-contract.md` | `chapters/ch04`, `ch08` |
| нужно понять, что говорит книга по теме | `references/source-map.md` | нужный `chapters/chNN` |

Полный список файлов с однострочным назначением приводится в `SKILL.md` ниже
роутера, чтобы каждый файл был достижим за один переход.

## 7. Гейт цитат

Основной механизм защиты от галлюцинаций. Сейчас валидатор проверяет только,
что номер строки не превышает длину файла: битую ссылку он ловит, ложную — нет.

### 7.1 L1 — anchor lock

Генератор `scripts/build_source_lock.py` собирает все якоря из `.md` скилла и
пишет `references/source-map.lock.json`:

```json
{
  "schema_version": 1,
  "book": {
    "upstream_commit": "97de455e9aa44cf9f93441ce0c771c9aa9643d92",
    "translation_commit": "ed2ae516d45dfe26e934cb390b80f105ca780b1f"
  },
  "anchors": {
    "chapter2.md:401": {
      "line_sha256": "<sha256 строки книги>",
      "line_text": "## KV-Cache: скрытое ограничение архитектуры",
      "kind": "heading"
    }
  },
  "allowed_inline": []
}
```

Валидатор:

- каждый якорь, встреченный в документах скилла, обязан присутствовать в lock;
- `sha256` строки книги по этому номеру обязан совпадать с `line_sha256`;
- расхождение — ошибка `anchor drift`, а не автоматическое обновление lock.

Это ловит любой сдвиг текста и требует, чтобы автор открыл строку, а не
угадал номер.

### 7.2 L2 — якорь указывает на заголовок

Ссылка обязана попадать на строку `^#{1,6}\s`. Исключения перечисляются в
`allowed_inline` с полем `reason`; пустой массив — дефолт. Правило закрепляет
уже существующую практику (100% текущих якорей — заголовки) и защищает от
хрупких ссылок в середину абзаца.

Диапазонные якоря вида `chapter2.md:763-935` проверяются по начальной строке;
конечная строка обязана быть в пределах файла и не меньше начальной.

### 7.3 L3 — дословная цитата в конспектах глав

В файлах `references/chapters/*.md` каждое фактическое утверждение о содержании
книги сопровождается дословным фрагментом:

```markdown
> «точный фрагмент из книги» — `references/source-book/chapter2.md:401`
```

Валидатор берёт **секцию якоря** — от строки-заголовка, на которую указывает
якорь, до следующего заголовка того же или более высокого уровня, — нормализует
её (склейка в одну строку, сжатие пробелов, унификация кавычек и тире) и
требует, чтобы текст цитаты входил в неё как подстрока. Длина цитаты:
3–200 символов.

Границей окна выбрана именно секция, а не фиксированное число строк. Замер по
`chapter2.md`: медианная секция — 16 строк, тогда как окно ±40 строк даёт около
13 000 символов и захватывает несколько соседних разделов, то есть пропускает
цитату, взятую не из того места, на которое ссылается автор.

Требование покрытия: цитата обязательна в разделе «Что решает глава» и в каждом
подразделе «Ключевых механизмов». В разделах «Таблицы решений», «Failure modes»,
«Проверки и метрики», «Антипаттерны» и «Связи» цитата не обязательна — это
авторский синтез, и принудительная цитата там породит натянутые ссылки вместо
проверяемых.

В `patterns.md`, `playbooks/*.md`, `templates/*.md`, `antipatterns.md` и
`SKILL.md` цитаты не требуются — там применяются только L1 и L2, потому что эти
файлы содержат авторский синтез, а не пересказ книги.

### 7.4 Что гейт не проверяет

Гейт подтверждает, что цитата взята из указанного места книги. Он не
подтверждает, что вывод, сделанный из цитаты, корректен. Смысловая корректность
остаётся зоной ответственности автора и code review.

## 8. Содержание слоёв

### 8.1 Конспекты глав (`chapters/ch00…ch11.md`)

Единый скелет каждого файла:

1. **Оглавление** — список разделов.
2. **Что решает глава** — 2–3 предложения.
3. **Ключевые механизмы** — 3–6 разделов, в каждом: определение, зачем нужен,
   как устроен, дословная цитата с якорем.
4. **Таблицы решений** — когда какой вариант выбирать.
5. **Failure modes** — наблюдаемые симптомы и что их вызывает.
6. **Проверки и метрики** — чем измеряется, что считается успехом.
7. **Антипаттерны главы** — ссылки на `antipatterns.md`.
8. **Связи** — какие `patterns.md` и `playbooks/` опираются на эту главу.

Критерий готовности конспекта — покрытие, а не объём: каждая тема, отнесённая к
этой главе в `source-map.md`, раскрыта как механизм с проверкой. Ориентировочный
объём 250–400 строк является следствием этого требования, а не целью; минимум по
числу строк не задаётся, чтобы не провоцировать воду.

Цель — агент читает конспект вместо 250 KB исходной главы и получает механизмы,
числа и проверки, а не тезисы.

### 8.2 `patterns.md`: 12 → 16 паттернов

Существующие 12 сохраняются, дополняются полем «сигналы, что паттерн нужен» и
«стоимость применения». Добавляются четыре, закрывающие непокрытые главы:

13. **Grounded Retrieval Layer** (гл. 3) — hybrid search, contextual retrieval,
    agentic RAG; provenance и проверка релевантности.
14. **Sessionless Resumable Worker** (гл. 5) — агент переживает рестарт,
    восстанавливается из durable state.
15. **Post-Training Decision Gate** (гл. 7) — когда fine-tuning оправдан, а
    когда это подмена отсутствующего eval-loop.
16. **Untrusted Content Firewall** (гл. 2, 4) — изоляция недоверенного
    retrieved/tool контента от инструкций и permissions.

Файл получает оглавление в начале.

### 8.3 `playbooks/` — 7 процедур

`design-agent.md`, `diagnose-trace.md`, `harness-review.md`, `build-evals.md`,
`memory-design.md`, `realtime-latency.md`, `multi-agent-choice.md`.

Единый скелет: когда применять → какие входы собрать до старта → пронумерованные
шаги, каждый с гейтом «не переходи дальше, пока не выполнено» → выходной
артефакт (ссылка на шаблон) → типичные ошибки → чем добрать.

Playbook — это процедура, а не пересказ главы: он говорит, что делать в каком
порядке и когда остановиться.

### 8.4 `templates/` — 6 артефактов

`agent-design.md`, `tool-contract.md`, `harness-spec.md`, `eval-plan.md`,
`memory-policy.md`, `trace-diagnosis.md`.

Каждый — заполняемая форма с обязательными полями и одним заполненным примером.
Обязательные поля помечены явно, чтобы агент не пропускал их молча.

### 8.5 `antipatterns.md`

Каталог: наблюдаемый симптом → почему возникает → чем заменить → якорь на книгу.
Ориентирован на диагностику: агент ищет по симптому, а не по названию ошибки.

## 9. Evals

- `evals.json`: 12 → 26 сценариев — 12 существующих, пересмотренных под новую
  структуру, плюс 14 новых. Покрытие обеспечивается суммарно: каждый playbook
  затронут минимум двумя сценариями, каждый шаблон — минимум одним.
- `trigger-evals.json`: 20 реалистичных запросов, из них 10 near-miss
  негативов, разделяющих ключевые слова со скиллом, но требующих другого
  (обычный REST-бэкенд, оптимизация одиночного промпта, починка CI,
  классический ETL, чат-бот на правилах без действий).
- Benchmark v3 (~52 запуска субагентов) выполняется отдельной фазой и только по
  явному разрешению пользователя.

## 11. Риски

| Риск | Смягчение |
|---|---|
| Цитаты раздувают конспекты | 1–3 цитаты на раздел, не больше |
| Гейт вырождается в формальность | окно ±40 строк вокруг якоря делает подгонку дороже, чем честная цитата |
| Дублирование между слоями | жёсткое разделение ролей (§5.1), кросс-ссылки вместо копирования |
| Роутер устаревает при добавлении файлов | `validate.py` проверяет, что каждый `.md` в `references/`, кроме `source-book/`, упомянут в `SKILL.md` |
| Рост `SKILL.md` сверх бюджета | проверка лимита 300 строк в `validate.py` |
| Объём работ (~6000 строк) | фазы независимы и проверяются гейтом на месте |
